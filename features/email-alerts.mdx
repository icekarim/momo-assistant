Runs every 5 minutes. Momo triages your inbox with Claude and pings you in Chat the moment something genuinely needs your attention — client emails, escalations, deadlines, blockers. Each alert fires once and is never duplicated. Alerted emails are also extracted into the knowledge graph for future cross-referencing.

## How it works

The `/email-alerts` endpoint (in `briefing.py`) is triggered by Cloud Scheduler every 5 minutes:

1. Fetches recent inbox emails matching the configured query
2. Filters out any already alerted (checked against Firestore)
3. Batches up to 10 unseen emails and runs Claude triage (returns JSON with `alert: true/false`, `priority`, `summary`)
4. Posts alerts to Chat for emails that pass triage; marks each as sent in Firestore to prevent duplicates
5. Triggers background knowledge graph extraction for each alerted email

## Configuration

Email alerts are configured via environment variables:

```env
EMAIL_ALERTS_ENABLED=true
EMAIL_ALERT_GMAIL_QUERY=is:unread in:inbox newer_than:2d
EMAIL_ALERTS_MAX_PER_RUN=5
IMPORTANT_EMAIL_KEYWORDS=urgent,asap,important,action required,deadline,escalation,blocker
CLIENT_EMAIL_KEYWORDS=client,customer
CLIENT_DOMAINS=
```

See the [environment variable reference](/setup/configuration#environment-variable-reference) for details on each setting.
